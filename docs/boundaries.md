# 能力边界与设计取舍

该应用是一套可演示的只读订单助手。新仓库默认不携带任何私人身份、服务密钥、历史任务或生产数据。以下区分实现能力和验证范围；本轮执行结果在 [验收记录](validation.md)。

| 部分 | 实现 | 边界 / 后续触发条件 |
|---|---|---|
| 订单事实与权限 | 服务端账号→角色→买家/店铺过滤，金额整数分 | 是预授权演示账号，不是电商平台登录体系；接真实用户前需正式身份、租户和数据权限审计。 |
| 售后规则 | 按支付时政策版本，收货时刻计算资格，完整条件和例外 | 受控合成规则，不支持任意合同解释；商品目录关联 T恤政策不等于真实 T恤订单售后全链路已接通。 |
| 泛政策与推荐 | 一般规则按查询时刻取版本；合成商品按预算/属性/范围筛选，另核适用条款 | 一般规则不判断具体订单，目录是固定历史快照；真实商品推荐、平台买家绑定及商家选品未完成。 |
| 平台订单与政策 | 独立商家店铺绑定后只读开发店；成功交易按原币与处理时间核算 | 当前政策快照不能证明支付时版本；未接平台买家身份和完整售后判断，不执行交易。 |
| 检索 | 先元数据过滤，后关键词/可选向量融合；必需规则条款不被截掉 | 默认三份政策共九个片段，未验证大规模召回、专用向量库或重排序收益。 |
| 条件管理 | 来源、明确修改、过期、订单变化和澄清；非法/冲突判断时间跨轮保留待澄清 | 不允许未来售后判断时刻；仅补商品状态不会自动改为当前时间。有限中文规则，不承诺任意自然语言识别；复杂表达需新失败样例和回归。 |
| 回答时间与引用 | 售后输出选取程序生成的结论目录；资格、条件、例外、运费分别绑定来源；不合格时有限修正或固定事实降级 | 历史首次漏引用失败保留。此修复约束可表达的结论，不等于能验证任意自由语言；原时间核验仍有有限表达范围。 |
| 长期记忆 | 金额格式、回答风格；账号＋角色隔离、版本及任务快照；四类新入口也使用快照和当前要求 | 元/分格式仅用于 CNY（人民币），外币保持原币最小单位，不按语言换汇。不写回临时要求，不改变历史回答；不是任意事件或权限记忆。 |
| 上下文 | 有限历史工具快照、来源摘要和条件状态；重复条款只保留可校验的统一引用 | 不是无限上下文或自动知识学习；历史事实不等于当前数据库事实，没有普遍性能或质量收益保证。 |
| 多智能体 | 金额/政策并行保留；售后先查订单事实，冻结交接，再解释政策并可有限补查，共享总预算 | 固定有限分工，补查不无限回环、不新增可信事实；未建立稳定优于单模型的准确率或成本结论。 |
| 协议工具 | 独立 MCP（Model Context Protocol，模型上下文协议）服务，认证与参数校验 | 本机内部网络、静态随机凭据；不是公开 OAuth（开放授权）服务。 |
| 程序化工具 | 受限语法和隔离容器、只读工具、共享预算 | Mac 本机运行模式有限验证；默认应用容器不具备创建执行容器的权限。 |
| 运行恢复 | 任务与过程记录持久化，重启标记中断，历史可读 | 不会从任意模型/工具节点自动无损续跑；已发往远端的请求取消后仍可能完成或计费。 |
| 飞书 | 白名单私聊、身份绑定、去重、收发分别记录 | 用户必须配置自己的测试应用；公共仓库不提供原作者凭据或已授权身份。 |
| 解释与引用 | 固定计算、结果结构/数字/引用核验、失败降级 | 无法保证所有自然语言语义正确；“已有原因记录”不能证明经营变化因果。 |
| 可信技能指引 | 仓库内独立文件、程序按业务状态选择、路径白名单与大小/格式检查，记录文件摘要 | 只有订单核查和售后两项；不是模型自主发现、下载或执行第三方技能，指引不能扩大权限。 |
| 售后简洁交付 | 模型选择受控结论，程序按结论及证据生成正文；完整政策原文及明细折叠、可导出 | 不截断条件和例外；既有历史文本保留。新入口的详略由渲染层执行，详略不改变业务结论或金额。 |
| 部署 | 本机环回端口、独立数据库/运行卷、默认无付费模型 | 不等于成熟公网服务；上线前还需 TLS（传输层安全）、密钥管理、审计、备份恢复、负载和租户测试。 |

## 默认与可选

- 默认：PostgreSQL（关系数据库）、独立协议服务、本机网页、合成数据、关键词检索与固定核查；不发送付费模型/嵌入请求。
- 明确可选：DeepSeek 解释、硅基流动嵌入、合成商品聊天、Shopify（电商平台）开发店只读、飞书、宿主短程序模式；逐项配置、逐项核验。
- 未强装：LangGraph（状态图框架）、专用向量数据库、重排序模型或优化器。出现可衡量需求后再比较代价，不为名称增加依赖。

## 技能指引的实际加载与成本

[`skill_loader.py`](../skill_loader.py) 只从固定的 `skills/` 目录加载代码白名单内文件，拒绝未知名称、符号链接、缺失文件、超长内容或不完整规范。文件包含职责、适用条件、步骤、输出规范和边界。选择依据是服务器生成的业务状态，不是用户提供的文件路径或工具返回的指令。加载失败会明确停止，不继续调用模型；文件编号及 SHA-256（内容摘要）保存在任务结果和模型调用记录中。可信前提是代码与指引一同审查发布，不意味着内容具有密码学签名或可以防御拥有项目写权限的人。

- 单笔、汇总、列表任务加载 [`order_check.md`](../skills/order_check.md)。售后任务加载 [`buyer_support.md`](../skills/buyer_support.md)。普通闲聊或纯政策任务不加载这两份文件。
- 旧双分支对照中，金额分支加载订单指引，政策分支沿用自己的职责提示。售后的多角色模式使用订单事实→政策解释的依赖顺序，不再转回单路；商品、泛政策和平台查询仍透明地使用各自受限单路。并非每个分支都有独立文件技能。
- 专用两期解释、原因调查、受限程序和快照 SQL（结构化查询语言）执行器没有因本次修改自动获得技能系统。它们已有各自受限流程；不能将单路测试扩大为所有运行模式通过。
- 文件加载本身不增加模型请求或工具调用，也不修改输出词元上限与共享预算。其内容进入模型输入，会影响输入词元和费用；当前未建立“技能加载能降低成本或提高准确率”的稳定对照结论。建议篇幅是软要求，实际输出仍受模型行为影响。

## 售后短答与完整依据

新售后任务由模型从已核对的结论目录中选择条目，再由程序产生文字和逐项引用，避免自由正文额外添加缺乏证据的结论。默认保留版本、适用时限、必要状态、定制例外与未知信息；完整原文、来源位置与工具结果在网页中展开查看，并随任务完整导出。模型校验失败时保留失败记录并按有限修正/固定事实降级，不把降级冒充模型成功。旧任务不会被回写；旧正文中已含的长原文仍保留。

完整依据折叠只是展示变化，不删除原证据。详略控制只影响展示层：简短保留业务结论、必要条件与来源；详细补处理状态、计算或相关原文。已有短泛政策答复在简短模式下仍保留完整条件，不为缩短而删去例外。不能用事实/引用通过代替简洁性验证。

## 平台

历史本机验证来自 Apple 芯片 Mac，Python 3.12。容器应用曾在 Linux ARM64（64位 ARM 架构）验证；本仓库固定 Python 基础镜像摘要，本次公开副本的免费链路已用独立空卷检查；真实外部调用与容器内免费检查分开，详见验收记录。未完成 Windows、Intel Mac、Linux AMD64（64位 x86 架构）以及云环境的完整验收；安装说明不构成这些平台已经通过的证据。

## 保留的未完项

平台真实商品、客户与本地买家绑定、完整平台售后链、政策更正/撤回与索引更新、商家选品、自然语言语义保证、规模化检索、跨平台部署、任意节点恢复和大规模安全/压力测试仍未完成。有限开发店商家查询不能替代这些目标。它们不被“自动测试通过”或“仓库公开”覆盖。

## 发布范围归类与最近触发点

| 状态 | 范围 | 下一触发条件与代价 |
